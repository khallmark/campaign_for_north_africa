# Repository Rules

- Kevin grants standing authorization to commit, push, merge in-scope project work into `main`, and deploy validated `main` to GitHub Pages without repetitive approval questions. Complete that delivery chain and verify the live release before calling the work shipped; do not stop at local changes or a merged branch. The Validate workflow automatically publishes main after both platform checks pass. Failed checks must be resolved, not bypassed. This does not authorize destructive operations, other deployments, or unrelated shared-state changes. Explicit task-specific restrictions still apply.
- Own failed checks through diagnosis, repair, and a passing rerun. Add focused regression or release checks when coverage is missing; do not weaken assertions, suppress failures, or treat a flaky rerun as a durable fix. Do not hand back failed validation as completed work. Report any genuine external blocker and the remaining delivery state clearly.
